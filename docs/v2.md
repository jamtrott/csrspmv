# 优化方案 v2

本分支 **从原始 master `9352c865044f4c8b344d6fe5a277200a89f7a08b` 创建**，与 `optimization/v1` 为并列分支。v1 内核、SELL 数据结构和 v1 提交历史不并入本分支；实验程序从固定 v1 提交独立构建对照。原始 `csr.c` 保持不变，默认仍执行 original。

## 使用

```sh
make CFLAGS='-O3 -march=native -g -Wall -iquote src -fopenmp'
OMP_NUM_THREADS=12 ./csrspmv test.mtx --kernel=v2 -v
OMP_NUM_THREADS=12 ./csrspmv input.mtx --kernel=v2 --v2-kernel=csr --partition=work -v
OMP_NUM_THREADS=24 ./csrspmv input.mtx --kernel=v2 --v2-kernel=merge --execution=parallel -v
make check CFLAGS='-O3 -march=native -g -Wall -iquote src -fopenmp'
```

| 选项 | 语义 |
| --- | --- |
| `--kernel=original\|v2` | 默认 original；v2 仅优化 f32/f32/f32，其他类型回到原始入口 |
| `--v2-kernel=auto\|csr\|short8\|merge` | 直接 CSR、固定 8 项展开或 merge；short8 要求完整行扫描确认，失败回到通用 CSR |
| `--partition=auto\|rows\|work` | 连续等行数或 nnz+rows 权重边界；显式 merge 只允许 auto |
| `--execution=auto\|serial\|parallel` | 真正串行入口或一次团队内重复计算；串行也逐次执行 y+=Ax |
| `--prefetch=0\|32\|128` | 行路径中按非零元距离前瞻；默认 0。short8 每行请求一个未来 x 元素，通用 CSR 每项请求；merge 不使用该预取 |
| `--serial-threshold=N` | auto 在 rows+nnz 不超过 N 时串行，默认 32768；这是本机保守试验规则，非通用最优值 |
| `--strict-order` | auto 禁止拆行；显式 merge 组合报错。不承诺与不同 FMA / 编译选项的原程序逐位相同 |
| `--plan-memory-mib=N` | merge scratch 上限，默认 4 MiB；超限或分配失败回到直接 CSR |

auto 不试算所有后端：完整检查并统计后，先处理串行规模；全行长 8 选 short8，其余选 CSR。等行数分区的最大 nnz+rows 超过平均的 1.5 倍时选 work。实际预估团队大于 1、最长行超过平均事件量两倍、允许重组求和且 partition=auto 时选 merge。阈值均为工程规则；未知收益不触发格式转换。正式结果见资料仓库 `experiments/2026-10-26-v2`，不应将这些规则视为跨机器保证。

## 实现与成本

- `spmv_plan.[ch]` 提供原始 / v2 分派和借用 CSR 的生命周期。
- `spmv_v2.[ch]` 实现完整验证、统计、边界搜索、直接短行、预取和分段归约。
- `main.c` 增加真正串行分支、计数溢出预检、实际团队与成本输出。重复并行区本来就在外层，未将其算作新增优化。
- 准备始终完整检查行指针和所有列号，不抽样，不信任仅指针相同的旧缓存。大输入的行扫描与列检查并行完成，两次团队开销均进入 prepare；行验证与统计融合计入 row_scan_s，策略及分配合计入 policy_s，不宣称已分离这些融合阶段。
- 行边界用现有 int64 row_ptr 二分 F(i)=row_ptr[i]+i，无 O(m) 新前缀数组；每线程 O(log m) 查询在执行中付费。该分区不拆巨行。
- merge 对行结束事件与 nnz 事件做稳定合并搜索，坐标 / 对角线为 int64；每线程最多两个边界片段，scratch 为 64*T 字节。跨线程行延迟合并并只加旧 y 一次，保留计算后与完成同步。实际团队超过容量时全部线程一致走安全行路径；较小团队重新计算边界。
- 无 SELL 转换、Ax 缓存或行重排；不以 R*Ax 替代 R 次调用。仅 v2 翻译单元关闭 FMA 合并；行函数局部禁止循环 / SLP 向量化，作为 v1 证据支持的候选，并非全局关闭向量化。保留 original 自动向量化对照。

## 接口与数值边界

prepare/free 在团队外调用；execute 由团队全部线程一致调用，或在团队外执行串行路径。x/y 不重叠，不允许并发团队共享 y。x/y 可逐次变化；直接 CSR 每次读取当前值，**结构变化必须显式重建计划**。本版没有自动版本检测，调用者不得修改 row_ptr / 列号后继续复用 short8 / 分区统计。

团队中的线程须提供一致的矩阵、向量、初始逻辑FLOP计数及调用次数；行列数或数值类型变更也须重建。CLI在进入团队前统一检查调用次数/计数范围，避免某个线程因可预见的参数错误提前退出集体同步。

保持行序的 CSR 路径从 sum=0 开始，最后加一次旧 y；空行也执行 y+=0，R=0 才不调用。merge 重组长行归约，按误差界验证而非普遍逐位保证；严格顺序模式不拆行。负参数、无效组合和计数溢出报错；零元矩阵配正 --flops 报错，避免无限循环。malloc 失败采用可测的一致回退，不制造物理 OOM。

## 一手来源与改编

1. 固定行展开及显式行区间参考 [Trotter 原作者归档](https://zenodo.org/records/7837264) `spmv-1.5.zip`，SHA-256 `33268b89c61c8eeb2c00bbbf871132104885222225562b9b5d43eda622362ed6`。`ellgemv16sd` 为 double ELL、16 项并含对角项；本版仅参考展开方法，独立写为 f32 CSR8。该归档 GPL-3.0-or-later。
2. merge-path 搜索适配 [Merrill/Garland 作者 CPU 源码](https://github.com/dumerrill/merge-spmv/blob/18895571ce9af960ee207dae541b0ffc701ea4bb/cpu_spmv.cpp#L211-L352)，commit `18895571ce9af960ee207dae541b0ffc701ea4bb`，源文件 SHA-256 `0afec976ff6fcf68b81d8b8996ee1fcbdd82802862fbb5a8104b2bce5af7744a`。原函数覆盖 y、固定 256 项、int 坐标；本版转换为 C/f32/int64、实际团队 scratch 和延迟 y+=Ax。原 BSD-3-Clause 全文保存在 [许可](merge-spmv-LICENSE.txt)，并保留于源文件头。
3. 非零元分区与预取实验参考 [Williams 等 SC07](https://people.eecs.berkeley.edu/~yelick/papers/spmv-multicore.pdf) §4 和 [Ainsworth/Jones CGO17](https://www.cl.cam.ac.uk/~tmj32/papers/docs/ainsworth17-cgo.pdf)。它们不证明本机参数最优；预取也可能增加指令、TLB 和流量成本。
4. 预取边界按 [GCC 11.4 builtin 文档](https://gcc.gnu.org/onlinedocs/gcc-11.4.0/gcc/Other-Builtins.html) 检查未来索引；同步遵循 [OpenMP worksharing](https://www.openmp.org/spec-html/5.2/openmpse66.html)。原始已有 CSR、OpenMP 和自动向量化均不算本人的新增贡献。

## 本轮验证结论

超大均匀矩阵24线程R=9，准备+执行+清理的独立进程中位数由0.811400 s降至0.734880 s，降低9.43%；相邻配对的加速比区间约[1.052,1.211]。这是本机主目标的结果，不是所有输入的统一保证。

同二进制诊断中，固定8项与通用CSR在超大矩阵各线程的差距接近1，未证实展开本身具有稳定独立优势。直接CSR、局部标量组织和低准备成本的组合应分开归因。short8保留为冻结实验候选，可强制选择csr；全局默认仍是original。集中长尾有明显收益，但99%空行、部分随机输入和双巨行保留集仍有退化；巨行也未超过v1-pack最强对照。完整正负结果和不确定性在资料仓库报告中保留，原始master未合并试验改动。
